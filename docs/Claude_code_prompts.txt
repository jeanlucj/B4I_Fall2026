[2026-09-21 20:48:57] I asked Claude App if there was a way to force one factor with loadings all equal to 1 in MegaLMM.  Here's what it said pasted below.  I suggest in this case making a branch to test this out since it is a big departure in the MegaLMM modeling.
There's already a fixed_factors mechanism and a Lambda_mean in the sampler. Let me see how they're set up.Good news first: MegaLMM already has this feature. I cloned the current source from GitHub and read the sampler code. There's an undocumented-in-vignettes argument, Lambda_fixed, that does exactly what you want. So the job is mainly configuration and validation, not modifying the package. 
The default setting has a detail that matters for your problem. The horseshoe's global scale is set from prop_0 = 0.1, a prior expectation that about 10% of loadings in a factor are nonzero. A main-effect factor has every loading nonzero, which is the densest possible factor, and the default prior is tuned against exactly that. This is a fourth reason, alongside Code's three mechanisms, why MegaLMM struggles to reconstruct the oat main effect. A fixed factor sidesteps it entirely.
How Lambda_fixed works
The feature is threaded through the sampler as follows:
Setup. setup_model_MegaLMM(..., Lambda_fixed = ...) takes a matrix of the first k rows of Λ. It builds a fixed_factors logical vector and sets Kr = K − k as the number of free factors.
Initialization. initialize_variables_MegaLMM writes the fixed rows into Λ.
Loadings update. sample_latent_traits subtracts F[, fixed]Λ[fixed, ] from the data before sampling. It then updates only Lambda[!fixed_factors, ], so the fixed rows are never touched.
Factor scores. Scores are sampled against the full Λ, fixed rows included, so f₁ is estimated from all of each oat's observations across every pea column. That is exactly the row-pooling you want.
Shrinkage priors. Both the horseshoe and ARD samplers compute precisions only for the Kr free rows. The fixed factor is exempt from shrinkage.
Reordering. reorder_factors keeps fixed factors first and reorders only the free ones.
The fixed factor still gets the level-2 model: f₁ = U_F1 + E_F1, with its own sampled h². So you get an oat main effect with kinship borrowing plus an iid non-genetic part. That is essentially DGE-IGE's Pr_i ~ N(0, G_oat σ²), with free factors layered on top for interaction.
The fallback also changes in the right direction. When the free factors shrink away, predictions collapse to μ_j + f₁ᵢ + U_R[i,j], the correct margin, instead of μ_j + U_R[i,j].
Three things to get right
1. Which API Code is using. Lambda_fixed exists only in the classic setup_model_MegaLMM() pipeline, which both vignettes use. The newer modular setup (MegaLMM_F(), MegaLMM_add_trait_matrix() in new_MegaLMM_setup.R) has the fixed-factor block commented out. If Code built on the new API, it would need to switch or port that block.
2. scale_Y. Fixed loadings apply on the scale the sampler works in. With the default scale_Y = TRUE, each pea column is standardized, so loadings of 1 mean "equal effect in each column's SD units." At 10 observations per column those SDs are noisy.
The better option is scale_Y = FALSE, after dividing all of Y by one global SD yourself. The other priors assume roughly unit scale.
3. The prior on the factor's variance. This is the one most likely to bite. With loadings fixed at 1, the oat main-effect variance equals var(f₁), which is controlled by tot_F_prec. Its default prior is tot_F_var = list(V = 18/20, nu = 20), an inverse gamma concentrated near 1. For free factors that's harmless, because scale trades off against Λ. For your fixed factor, it would pin the main-effect variance near 0.9 of the unit scale regardless of the data.
The code accepts length-K vectors here, so you can loosen the prior for factor 1 only.
A sketch of the setup (I've written n_fac to avoid a clash with the kinship K; adapt the formula to your data):
p <- ncol(Y); n_fac <- 6
Y_s <- Y / sd(Y, na.rm = TRUE)          # one global scale, not per column

run_parameters <- MegaLMM_control(scale_Y = FALSE, K = n_fac, ...)
state <- setup_model_MegaLMM(
  Y_s, formula = ~ 1 + (1 | Oat), data = oat_data,
  relmat = list(Oat = K_oat),
  Lambda_fixed = matrix(1, nrow = 1, ncol = p),
  run_parameters = run_parameters, run_ID = "fixed_main_effect")

priors <- MegaLMM_priors(
  tot_F_var = list(V  = c(0.5, rep(18/20, n_fac - 1)),
                   nu = c(3,   rep(20,    n_fac - 1))))
state <- set_priors_MegaLMM(state, priors)

A cosmetic quirk: when posterior samples are saved, remove_nuisance_parameters rescales Λ by √var(F) so that factors have unit variance. Factor 1's saved loadings will therefore all equal the main-effect SD rather than 1. That's expected, not a bug.

## Kronecker interaction basis

**Eigenvectors / scaling** — `grm_basis()` at `dge_ige_functions.R:140-151`:
```r
grm_basis &lt;- function(G, rank = NULL, variance = NULL) {
  e &lt;- eigen(G, symmetric = TRUE)
  vals &lt;- pmax(e$values, 0)
  k &lt;- if (!is.null(rank)) { min(rank, sum(vals &gt; 1e-8 * max(vals))) }
       else { which(cumsum(vals) / sum(vals) &gt;= variance)[1] }
  V &lt;- sweep(e$vectors[, seq_len(k), drop = FALSE], 2, sqrt(vals[seq_len(k)]), "*")
  rownames(V) &lt;- rownames(G)
  V
}
```
So: `eigen(G, symmetric = TRUE)` leading `k` eigenvectors, **scaled by `sqrt(eigenvalue)`** (i.e. `A = U Λ^½`, so `A A' = G`), eigenvalues floored at 0, rank capped at the non-null count. **`rownames` are set; `colnames` are NOT.**

**Column ordering** — `kron_basis()` at `dge_ige_functions.R:168-172`:
```r
kron_basis &lt;- function(A, B, oat_idx, pea_idx) {
  ka &lt;- ncol(A); kb &lt;- ncol(B)
  A[oat_idx, rep(seq_len(ka), each  = kb), drop = FALSE] *
    B[pea_idx, rep(seq_len(kb), times = ka), drop = FALSE]
}
```
Column `c = (p-1)*kb + q` holds `A[,p] * B[,q]` — row-wise Kronecker / Khatri-Rao, **row-major in (oat index, pea index)**. Confirmed by the test at `tests/test_kronecker.R:46-52` and documented in `docs/specific-combination_kronecker.md` (step 2, the `rep()` table).

**Column names do NOT encode the eigenvector pair.** `grm_basis()` sets no colnames, and `kron_basis()` returns a bare elementwise product of two subsetted matrices — the result has no column dimnames at all. The `(p, q)` pair is recoverable only from arithmetic on the position, and the companion reshape at `dge_ige_functions.R:395-396` relies on that:
```r
Beta &lt;- matrix(b[, match(trait, DGE_IGE_TRAITS)],
               nrow = ncol(kron_A), ncol = ncol(kron_B), byrow = TRUE)
```
`byrow = TRUE` is load-bearing (comment at lines 388-391; "Why it is fragile" section of `docs/specific-combination_kronecker.md`).

# 3. Simulation ground truth for the interaction — `code/sim_generate.R`

## Construction from `n_factors` — `sim_generate.R:278-290`
```r
  draw_interaction &lt;- function() {
    if (!(n_factors &gt; 0 &amp;&amp; V_I &gt; 0)) {
      return(list(I = matrix(0, n_oat, n_pea), U = NULL, Lambda = NULL))
    }
    U   &lt;- vapply(seq_len(n_factors), \(f) draw_effect(L_oat, 1), numeric(n_oat))
    Lam &lt;- vapply(seq_len(n_factors), \(f) draw_effect(L_pea, 1), numeric(n_pea))
    I &lt;- (U %*% t(Lam)) / sqrt(n_factors)
    I &lt;- I * sqrt(V_I / stats::var(as.vector(I)))
    list(I = I, U = U, Lambda = Lam)
  }
  int_oat &lt;- draw_interaction()
  int_pea &lt;- draw_interaction()
```
- `U` is `n_oat x n_factors`, **oat scores**, each column a `draw_effect(L_oat, 1)` — covariance `G_oat`, empirically rescaled to **variance exactly 1**, mean-centred (`draw_effect()` at `:64-69`).
- `Lam` is `n_pea x n_factors`, **pea loadings**, same treatment with `L_pea`.
- Two surfaces drawn **independently** (`int_oat`, `int_pea`) — rationale at `:272-277`.
- **Important for any comparison:** the global rescaling `I * sqrt(V_I / var(vec(I)))` is folded into `I` only. The stored `U` and `Lambda` are *not* rescaled, so `U %*% t(Lambda)` does **not** equal `I`; it equals `I` up to the scalar `sqrt(n_factors) / sqrt(V_I/var(...))`. Comparison of a recovered score against `U_oat` is therefore valid only up to scale (and, for `n_factors &gt; 1`, up to rotation within the factor space).
- When `n_factors == 0` or `interaction_pct == 0`, `U` and `Lambda` are `NULL` and `I` is an all-zero matrix.

## 2. Risks you haven't named

**The burn-in trap (highest severity, silent).** In `BGLR::Multitrait` the `saveEffects` `writeBin` sits inside `if (iter %% thin == 0)` (deparsed line 332), *not* inside the `(iter &gt; burnIn) &amp; (iter %% thin == 0)` accumulation block (line 346). The header records `nRow = nIter/thin`, and `readBinMatMultitrait` hands back **all** of them, burn-in included. At the current `nIter = 6000, burnIn = 1000, thin = 10` that is 600 rows of which the first 100 are burn-in — not the "400–1000 draws" in your note. Forget the offset and every posterior SD inflates and the spectrum flattens, which is indistinguishable from the §(c) bias you are trying to measure.

**Also verified, so you can rely on it:** `storageMode` defaults to `"double"` (`setLT.BRR_mt`), compression is opt-in (`compressEffects`, default off) and `gzfile` reads uncompressed anyway, `as.vector(beta)` on a `p × traits` matrix is column-major and the reader's `for k in 1:traits { Beta[j,,k] &lt;- readBin(n = p) }` matches it, and `fit$ETA$G_mix$beta` is the posterior *mean* (`$beta &lt;- $post_beta`, line 419). That last fact gives you a decisive test.

**(a) Alignment.** Signed permutation is enough only where the spectrum separates. Near-ties produce a *continuous* rotation of the degenerate block that a signed permutation cannot represent; it will report large posterior SD on individual scores while the subspace is perfectly well determined. Near the noise floor nothing helps. So: make the rotation-invariant quantities primary (the `d_k²` shares and the top-`r` subspace), use block-diagonal Procrustes (full `Q` from `svd(U_ref' U_draw)` within blocks where `(d_k - d_{k+1})/d_1 &lt; 0.05`, signed permutation between blocks), and take the reference from the decomposition of the posterior-**mean** surface, not draw 1. Report four diagnostics: posterior distribution of the gap ratio; mean `|diag(Q)|` (1 = stable); posterior mean principal angles between each draw's top-`r` subspace and the reference (alignment-free); and the label-switch rate. One more: singular values are convex in `M`, so `E[d_k(M)] ≥ d_k(E[M])` — the draw-wise spectrum is systematically flatter and heavier than the spectrum of the mean surface. Report both, and name the mean-surface spectrum as the point estimate. Finally, 500 kept draws at thin 10 on 900 coefficients is thin: record `coda::effectiveSize(d_1)` per cell and mark cells with ESS &lt; 100 uncertified rather than quoting their intervals.

**(b) Disk and memory.** Per fit: 24-byte header + 600 × 900 × 2 × 8 = **8.64 MB** (4.32 MB at `storageMode = "single"`). The sweep is 600 `dge_ige` fits (`fixed_main_effect` only changes MegaLMM), so 5.2 GB / 2.6 GB. Peak memory is trivial (one 8.6 MB array). Real hazards: (i) `saveAt` is a prefix, so pointing it at `output/` in a 20-task array makes every task write `output/ETA_G_mix_beta.bin` and clobber the rest — keep it in the per-process `tempdir()` and decompose in-process; (ii) do **not** cache per-draw score matrices (400 × 5 × 500 × 8 ≈ 9.6 MB per trait per cell, &gt;11 GB); cache per-draw `d` (24 KB), aligned score mean/sd, and diagnostics; (iii) **do** cache the raw `[n_keep, 900, 2]` Beta array per cell — 2.6 GB at single precision buys you the ability to redo every decomposition choice (centred vs raw, rank, alignment method) in seconds instead of re-running a 70-hour refit. That is the single highest-value caching decision here; (iv) a killed job leaves a truncated `.bin` that reads as an NA-filled array with no error, hence the size assertion in `read_beta_draws`.

**(c) Does BRR flatten the spectrum?** Yes, two ways, and they are separable. The prior is one scalar variance over all `q²` coefficients (times a 2×2 UN `Omega` across traits). First, shrinkage that does not scale with signal strength compresses `d_1/d_k` and inflates any share- or participation-ratio-based effective rank. Second, isotropy *in Beta space* means the implied prior on the surface has covariance `Λ_a ⊗ Λ_b`, so the posterior is tilted toward leading GRM eigen-directions irrespective of where the truth sits, and the recovered loadings inherit the GRM spectrum. Measure both: **null calibration** — add `interaction_pct = 0` / `V_I = 0` cells (the generator supports it; `SIM_INT_LEVELS` deliberately has no such level) and record the fitted spectrum under no true interaction; that is your `d_k^null` noise floor, and effective rank must be read against it. If the `n_factors = 1` cells return the same effective rank as the null, the spectrum carries no rank information and the honest deliverable shrinks to the leading direction plus a caveat. **Rank tracking** — regress estimated effective rank on true `n_factors` (1/3/5) and report the slope; slope ≈ 0 with a large intercept *is* the flattening bias, quantified. **Tilt test** — compare recovered loadings' overlap with the leading `G_pea` eigenvectors against the truth's own overlap; systematic excess is the `Λ_a ⊗ Λ_b` tilt. **Sensitivity** — refit one cell with basis columns scaled as `Λ^α`, α ∈ {0.25, 0.5, 1}: same span, different implied surface prior; if the shares move materially they are prior-driven. Report shares on the centred surface only, consistently — centring removes the additive directions where much of the uniform-shrinkage bias lives.

**(d) The `kron_rank` confound, which is worse here than for `r_int`.** Loadings are confined *by construction* to `span(V_b[,1:q])` and scores to `span(V_a[,1:q])`, while the truth's `U`/`Lambda` are `draw_effect(L, 1)` draws with mass on every direction. So there is a hard analytic ceiling on any subspace-recovery number, and it is computable with **no fitting**: the canonical correlations between `span(truth$U_oat)` and `span(kron_A)`. Add that column and report recovery as a *fraction of ceiling*; without it, every number at `kron_rank = 30` is uninterpretable in exactly the way `sim_kron_study.R:1-70` describes. Two consequences: the `n_acc` main effect (30/200 vs 30/400 directions retained) is partly a truncation artefact that only the ceiling column separates; and the decomposition needs its own truncation-free anchor — get it free by adding the decomposition responses to `sim_kron_study.R`'s existing `n_acc = 60/100, ranks = ..., full` design rather than building a second anchor. At `rank = full` the spectrum question becomes purely about shrinkage, so that anchor serves (c) as well.

**Scope risk you haven't named.** `code/BGLR_multi_trait_model.R:94` sets `fit_mix_term &lt;- FALSE`, and when it is TRUE it builds the **exact** combination kernel inline (`Z_mix %*% L_mix`, lines 332–355) rather than calling `fit_producer_associate`. So (i) there is currently no fitted interaction surface for the real experiment at all, (ii) the exact-kernel form is not bilinear and this decomposition does not apply to it, and (iii) Step 2's plumbing does not reach that script. Meanwhile its own guard at line 233 says the mix term is near-inestimable on the real data (&gt;90% of combinations unreplicated). Decide explicitly now whether the deliverable is simulation-only, or whether the production script gets switched to `fit_producer_associate(kron_rank = ...)`.

**Smaller ones.** `grm_basis` caps `k` at the non-null directions, so `ncol(A)` and `ncol(B)` can differ and be below `kron_rank` — assert `ncol(A)*ncol(B) == nrow(beta)` and never assume square. `eigen()` sign is arbitrary-but-deterministic: recomputing `kron_A` post hoc under a different BLAS silently flips scores, so store the bases rather than rebuilding them. Component-level agreement must be reported as `|cor|` (joint score/loading sign is unidentified). And because the generator rescales only `I`, `truth$U %*% t(truth$Lambda) != truth$I_oat`; compute the truth-side spectrum from `truth$I_*` (or rescale `U`/`Lambda` identically) or the shares will look wrong by a constant and be misread as bias.
